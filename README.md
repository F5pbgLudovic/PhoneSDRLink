# PhoneSDRLink

**Français** — Application Android (APK) du radioamateur F5PBG qui reprend les fonctions de réception de [SDRLink](https://github.com/F5pbgLudovic/SDRLink), sans la télécommande du poste : on écoute un WebSDR (websdr.org, KiwiSDR, OpenWebRX, UberSDR, PhantomSDR) depuis son smartphone.

## Fonctions

* **WEBSDR** : favoris en listes (grandes cases), recherche dans les annuaires publics (websdr.org, KiwiSDR, ReceiverBook) au premier démarrage puis à la demande, gestion des favoris comme SDRLink (renommer, déplacer, vérifier, importer, exporter, **écouter la sélection sans quitter la fenêtre** : le WebSDR joue derrière), adresse libre. Le son démarre sans action, comme dans SDRLink.
* **Fréquence** (1,8 à 440 MHz) : un appui ouvre un clavier (saisie en kHz). **Mode** USB / LSB / AM / FM / DATA / CW ; **appui long sur le mode : largeur de bande** du signal (2,1 / 2,4 / 2,6 / 2,8 / 2,9 / 3 / 4 kHz, ou une valeur de 0,3 à 12 kHz ; réglée dans le WebSDR lui-même : websdr.org, KiwiSDR, OpenWebRX, UberSDR, PhantomSDR). **Barre à glisser** (droite = plus haut) avec pas de 1 Hz (USB/LSB seulement) à 10 kHz (1 Hz, 10 Hz, 50 Hz, 100 Hz, 250 Hz, 500 Hz, 1 kHz, 10 kHz) ; un geste rapide la lance comme une roue qui ralentit, un doigt posé l'arrête.
* **Scan** de fréquences ou de mémoires, **Conf scan** (zones non scannées, profils nommés), **Mémoires** en listes. Un appui dans la page arrête le scan.
* **REC** : enregistre le son du WebSDR en MP3 dans `Musique/PhoneSDRLink` (appui long : ouvre ce dossier dans l'application Fichiers).
* **Muet** (appui long : **minuterie** de 15, 30, 45, 60 minutes ou une durée au choix ; le son est coupé puis l'application se ferme ; si un REC est en cours, l'application demande quand l'arrêter, éventuellement après la coupure du son, et ne se ferme qu'à la fin du REC), **Verrou** (rouge = plus rien ne peut être modifié, **INIT**, **+** et **−** compris ; seuls Muet et Verrou restent actifs), **INIT** (relance le WebSDR si le son s'arrête et remet l'affichage d'origine, zoom compris), **+ / −** (taille de la page ; le zoom, à la main ou avec + et −, n'est pas modifié par un changement de fréquence).
* **Zoom du spectre** automatique : 3 kHz de spectre pour environ 3 mm d'écran (websdr.org, KiwiSDR, OpenWebRX, UberSDR).
* **SET** : mode sombre, notch automatique (DNF) et réducteur de bruit (DNR) avec 10 niveaux chacun, réinitialisation automatique du WebSDR après 30 s sans son, écran toujours allumé, couleurs de l'écran (fond, boutons, fréquence, réglette), langue (23), mise à jour, nom donné aux WebSDR, import/export des réglages (compatible SDRLink pour PC), réinitialisation.
* Le volume du WebSDR suit les touches de volume du téléphone ; le son est coupé pendant un appel ; portrait et paysage automatiques.
* **Écran éteint** : l'écoute continue, sans saccades (service de lecture avec notification « Écoute du WebSDR en cours »). Si le son saccade quand même (téléphone à batterie très stricte : OnePlus, Xiaomi…), mettre la batterie de PhoneSDRLink sur « Sans restriction » (Paramètres › Applications › PhoneSDRLink › Batterie). Android 13 ou plus : accepter les notifications. Le tampon audio est large (environ 80 ms) pour que le son ne saccade pas, même pendant un REC.

## Appuis longs et gestes

* **Mode (appui long) : largeur de bande.** Les largeurs proposées dépendent du mode (USB/LSB 2,1 à 5 kHz, 2,9 kHz compris ; CW 100 à 800 Hz ; AM 6, 8, 10 kHz ; FM 8 à 15 kHz ; DATA 200 Hz à 4 kHz), ou « Autre valeur » (0,1 à 15 kHz), ou revenir au « filtre d'origine du WebSDR ». Le réglage est fait dans le WebSDR (websdr.org, KiwiSDR, OpenWebRX, UberSDR, PhantomSDR) ; la largeur choisie s'affiche sous le mode (par exemple « USB 2,4k »). En SSB le bord du filtre est à 300 Hz de la porteuse, en AM, FM et CW le filtre reste centré. Elle est remise après un changement de mode et au rechargement de la page, et revient au filtre d'origine quand on ouvre un autre WebSDR.
* **Muet (appui long) : minuterie.** 15, 30, 45, 60 minutes ou une durée au choix : à l'échéance le son est coupé, puis l'application se ferme (le bouton affiche le temps restant ; un nouvel appui long permet d'annuler). Si un REC est en cours, l'application demande dans combien de temps l'arrêter : en même temps que le son, ou plus tard (le REC enregistre le son avant la coupure, il continue donc après) ; l'application se ferme seulement quand le fichier MP3 est sauvegardé. Sans heure d'arrêt donnée au REC, il s'arrête avec le son.
* **REC (appui long)** : ouvre le dossier des enregistrements.
* **Barre à glisser** : un geste rapide lance la barre comme une roue qui ralentit peu à peu ; poser le doigt dessus l'arrête.
* **Gérer les favoris › Écouter la sélection** : le WebSDR sélectionné joue derrière la fenêtre, qui reste ouverte (on peut enchaîner les essais avant de ranger ses favoris).
* **REC qui continue** : changer de WebSDR ou appuyer sur INIT n'arrête plus l'enregistrement ; il reprend dans le même fichier MP3 dès que le son du nouveau WebSDR démarre (trou de 2 à 3 secondes).
* **WEBSDR › loupe** (à droite du nom de la liste) : un champ de recherche filtre la liste en cours, par nom ou par adresse.
* **SET › Nom ou indicatif donné aux WebSDR** : les espaces sont remplacés par le caractère invisible Alt+255 (espace insécable), que les WebSDR prennent en compte ; un nom réduit à un espace est donc invisible.
* **Mises à jour** : SET › « Vérifier les mises à jour » reste dans SET ; avec « Vérifier les mises à jour au démarrage » cochée, une alerte « Mise à jour disponible » propose d'installer : l'APK de la release GitHub est téléchargé puis installé par Android (qui demande d'abord d'autoriser l'installation depuis PhoneSDRLink, puis de confirmer). Sans APK ou en cas d'échec, la page GitHub s'ouvre.
* **Pas et largeur de bande par mode** : en CW le pas est de 10 Hz au départ, en USB/LSB de 1 kHz ; la largeur de bande par défaut est de 300 Hz en CW, 2,9 kHz en USB/LSB, 6 kHz en AM et 8 kHz en FM. Le pas ou la largeur que vous choisissez pour un mode devient celui de ce mode (USB et LSB vont ensemble), sur tous les WebSDR et après un redémarrage. « Réinitialiser le programme » (réinitialisation totale) remet les valeurs d'origine.
* **Notch et réducteur de bruit à 10 niveaux** : dans SET, un petit menu déroulant à côté de « Notch automatique » et de « Réducteur de bruit » choisit le niveau de 1 (réglage d'origine) à 10 (le plus agressif). Le notch automatique est coupé en CW et en DATA (la coche n'est pas modifiée).
* **Réinitialisation automatique WEBSDR** (SET) : si le son est perdu pendant 30 secondes, la page du WebSDR est rechargée, sauf si le volume est à zéro ou coupé (volume du téléphone, Muet, curseur de volume ou bouton mute de la page). Trois essais de suite au plus par WebSDR.
* **Gestion des favoris** : loupe de recherche sur la première ligne (liste HF), touche ▲▲ qui monte le favori sélectionné tout en haut de sa liste, et couleur des lignes après « Vérifier les favoris » : vert = répond, orange = sans réponse depuis une semaine, rouge = depuis un mois (la couleur est conservée à la réouverture ; un favori qui répond de nouveau repasse au vert).
* **USB/LSB** : largeur de bande 2,6 kHz ajoutée, pas de 1 Hz ajouté. Le nom de l'application, la version et « @F5PBG 2026 » s'affichent en tout petit sous la fréquence quand la place le permet.
* **Barre de réglage en bas** : un appui de 2 secondes (1.11 ; 3 secondes avant) sur la barre ouvre un menu Haut / Bas ; « Bas » la place tout en bas de l'écran (INIT, + et − remontent pour ne pas la toucher).
* **Boutons INIT, + et − : 8 positions** (1.11) : un appui de 2 secondes sur + ou − ouvre un menu : les quatre coins de la zone WebSDR (bas droite = position d'origine, bas gauche, haut droite, haut gauche), en colonne (vertical) ou en ligne (horizontal), utile quand ils masquent des commandes du WebSDR. Les lignes du décodeur affichées en bas de l'écran principal laissent la place aux boutons.
* **Mémoires** : loupe de recherche à droite du nom de la liste, et une case (bouton arrondi) par mémoire. **Liste « Modes numériques »** (1.11, dernière ligne du menu des listes) : les fréquences habituelles du mode du décodeur (celui qui tourne, sinon le dernier choisi dans la fenêtre du décodeur) pour les bandes de 1,8 à 440 MHz : FT8, FT4, WSPR, JT9 (table des fréquences par défaut de WSJT-X), PSK31, RTTY, SSTV, CW (fréquences d'appel QRP), FreeDV RADE. Un menu choisit la **région IARU** (1 Europe-Afrique, 2 Amériques, 3 Asie-Pacifique) quand les fréquences diffèrent (par exemple PSK31, RTTY et SSTV sur 40 m). Un appui va à la fréquence ; un appui long la copie dans l'une de vos listes. Quand un mode numérique est actif, les Mémoires s'ouvrent directement sur cette liste ; sans mode numérique actif, elles reviennent à la liste habituelle. À la réouverture des Mémoires (même après avoir fermé et relancé l'application), on revient à la même liste et au même endroit dans la liste. Même chose pour les listes de la fenêtre WEBSDR et de « Gérer les favoris… » (positions enregistrées dans les réglages) ; pour les résultats de « Chercher des WebSDR… », la position est retrouvée tant que l'application tourne. Ce sont des fréquences d'usage, à vérifier avec le plan de bande du pays ; les fréquences FreeDV (hors 14.236 et 7.177) sont à confirmer avec FreeDV Reporter.
* **Nom du mode numérique actif** (1.11) : quand un décodeur tourne, son nom (FT8, WSPR, PSK31…) s'écrit en tout petit, en rouge, dans le coin droit en bas de la case de la fréquence (même taille que « PhoneSDRLink V… »). Sa couleur se change dans SET › Couleurs… (« Mode numérique actif (case de la fréquence) »).
* **Notch et réducteur de bruit en mode numérique** (1.11) : tant qu'un décodeur tourne, le notch automatique (DNF) et le réducteur de bruit (DNR) sont coupés pour le son écouté (ils abîment les signaux numériques), même si leurs cases restent cochées ; ils redeviennent actifs à l'arrêt du décodeur. Le décodeur lui-même analyse le son brut, avant ces filtres.
* **Zoom de l'écran retenu par WebSDR** (1.11) : le zoom fait à la main (pincement) ou avec + et − est noté pour chaque WebSDR (dans les réglages) et retrouvé quand on revient sur ce WebSDR après en avoir visité un autre, et à la relance de l'application. **INIT** remet l'affichage d'origine et fait oublier le zoom de ce WebSDR.
* **FreeDV RADE V1 et V2** (1.11) : deux entrées dans la liste du décodeur, **RADE V1** (FreeDV 2.x, version de référence) et **RADE V2** (FreeDV 3.0, **encore en développement**). La V2 est prise de `freedv/rade_c` tel qu'il était le 6 novembre 2026 : son signal et ses réseaux de neurones peuvent changer sans préavis et ne sont pas compatibles avec la V1 ; elle ne décodera donc pas forcément les signaux V2 à venir. Elle a l'avantage d'un réglage automatique du niveau d'entrée. Essayée seulement en bouclage (émetteur V2 -> bruit -> récepteur, dans le téléphone : synchronisée et parole produite à 20 et 30 dB, 59 blocs sur 1000 à 10 dB, rien à 5 dB et moins) car aucun enregistrement V2 réel n'existe ; jamais testée sur un vrai signal. Ajout au poids de l'APK : 9,8 Mo -> 17,2 Mo. Le bouton FreeDV auto utilise la V1.
* **FreeDV RADE aligné sur FreeDV 2.4.1** (1.11) : le récepteur RADE V1 reprend les sources de la version de référence utilisée par FreeDV 2.4.1 (freedv-gui 2.4.1 → freedv-backend 1.0.1 → dépôt freedv/rade_c, Opus au même commit 940d4e5). Les poids du réseau de neurones sont identiques ; trois corrections de rade_c sont reprises : décalage d'un échantillon dans le tampon d'entrée, renormalisation de phase contre la dérive sur les longues réceptions (démodulateur et filtre d'entrée), et étalonnage de l'estimation du rapport signal/bruit affiché (il peut paraître 0,5 dB plus bas qu'avant). Le signal est maintenant donné au récepteur comme dans FreeDV 2.4.1 (signal réel, sans filtre de Hilbert). Essai sur l'enregistrement hors antenne de référence (FDV_offair.wav, 327 s) : même nombre de secondes synchronisées (314) et d'échantillons de parole qu'avant. RADE V2 (en développement, réservé à FreeDV 3.0) n'est pas inclus. Pas décodé : l'indicatif envoyé en fin de transmission (EOO) que FreeDV 2.4.1 affiche.
* **Mémoire tampon audio supplémentaire** (SET, 1.11, essai) : menu Aucune / 0,25 / 0,5 / 1 / 2 / 3 s. Il demande au WebSDR une plus grande mémoire tampon de sortie audio (latence en plus, dans l'espoir de supprimer de petites coupures) ; le WebSDR est rechargé quand on change la valeur. Il n'agit que sur la sortie audio d'Android : des coupures qui viennent du flux réseau du WebSDR (visibles dans le cadre de statistiques de l'UberSDR, ligne AUDIO, « drops ») n'en sont pas corrigées.
* **Couleurs de l'écran** (SET › Couleurs…, fenêtre à part ; exportées et importées avec les réglages) : choix par palette (ou couleur personnalisée en RVB, 0 à 255) du fond général, de la couleur de fond et du texte des boutons, du texte et du fond de la fréquence, de l'avant-plan et du fond de la réglette. Un texte ne peut pas prendre la couleur de son fond (la couleur est refusée) ; « Couleurs par défaut » remet tout comme à l'installation.
* **Décodeurs numériques** (SET › premier bouton « Décodeur FT8 / FT4 / WSPR / JT9 / CW / RTTY / PSK31 / SSTV / FreeDV… », coche **FreeDV auto**) : FT8, FT4, WSPR, JT9, CW, RTTY, PSK31, SSTV (images enregistrées automatiquement) et FreeDV RADE V1 sur le son du WebSDR, voir la section *Décodeurs* plus bas.
* **KiwiSDR** : changer de fréquence avec la réglette ne dézoome plus la cascade (le zoom actuel est conservé).
* **Boutons de l'oreillette ou du casque** (SET › « Boutons du casque (arrêt / départ du scan) », décochée par défaut) : un appui simple arrête le scan, ou le lance s'il est arrêté ; après un arrêt par le casque, un **double appui recule d'un pas de scan** (répétable, utile si l'on a arrêté trop tard), puis un appui simple reprend. Oreillettes et casques Bluetooth ou filaires (essayé avec un Sony WH-1000XM4) ; pas de micro, rien ne tourne tant qu'on n'appuie pas ; décochée, les boutons du casque sont ignorés.
* **Appui long sur Verrou** : quitter l'application (avec confirmation ; un REC en cours est sauvegardé).
## Décodeurs (FT8, FT4, WSPR, JT9, CW, RTTY, PSK31, SSTV, FreeDV RADE)

**Ouvrir** : SET › premier bouton « Décodeur FT8 / FT4 / WSPR / JT9 / CW / RTTY / PSK31 / SSTV / FreeDV… ». La fenêtre (1.11) propose : une **liste déroulante** des modes ; à côté, un **bouton portant le nom du mode choisi** (un appui lance le décodeur, il passe au **vert** tant que ce mode tourne) ; un bouton **STOP** (**rouge** quand un décodeur tourne, grisé sinon) ; **choisir un mode dans la liste le lance tout de suite** (le bouton passe au vert) ; après **STOP**, un appui sur le bouton du mode le relance ; un petit bouton **ⓘ Info** dont le texte change avec le mode (conditions d'emploi, fréquences usuelles, colonnes affichées) ; **Réglages (SET)…** et une case pour afficher les derniers messages sur l'écran principal. Le décodeur analyse le son brut du WebSDR (avant volume, Muet, notch et réducteur de bruit) : **il fonctionne même si le son est coupé**. Un seul décodeur à la fois (sauf FreeDV auto, voir plus bas). Tant qu'un décodeur tourne, le bouton **SET** de l'écran principal ramène dans la fenêtre du décodeur (« Réglages (SET)… » ouvre les réglages) ; le décodeur continue même quand on revient voir le spectre, et change de page WebSDR sans qu'on le relance. Il ne s'arrête que par **Arrêter**.

**FT8 et FT4** : mode USB ou DATA, sur une fréquence FT8 ou FT4 (par exemple 7.074 et 7.0475, 14.074 et 14.080 MHz). L'heure du téléphone doit être exacte (synchronisation automatique de l'heure). Le son est découpé en tranches de 15 s (FT8) ou 7,5 s (FT4) alignées sur l'heure UTC, chacune décodée par ft8_lib dans un fil à part. Chaque message s'affiche avec l'heure UTC de la tranche, le **DT** (écart de temps en secondes), la fréquence audio (Hz) et le texte (indicatifs hachés <...> comme dans WSJT-X). Le **retard du son** (réseau, WebSDR : 1 à 1,5 s sur un KiwiSDR) est appris tout seul à partir du DT des messages décodés. Pas de colonne SNR (celui de la bibliothèque n'est qu'un score, pas des dB). **Les deux périodes** (paire et impaire) s'affichent en **deux couleurs**, jaune et blanc par défaut, au choix dans SET › Couleurs… › « Décodeur : période 1 / période 2 » (palette ou RVB ; une période ne peut pas avoir la couleur de l'autre ni celle du fond). Essayé en direct : 20 messages dès la première tranche FT8, 42 messages en 5 tranches FT4.

**Écran principal** : en FT8 et FT4, **toute la dernière période** reste affichée en bas de l'écran, à côté de INIT, + et −, tant qu'elle tient sur la partie WebSDR (autant de lignes qu'il en tient) ; en CW et RTTY, les 6 dernières lignes ; en FreeDV, rien devant le spectre. On peut ainsi déplacer la fréquence en regardant le décodage. Un appui sur ces lignes ouvre la fenêtre du décodeur ; la case de la fenêtre les masque.

**CW** : mode CW ou USB, sur un signal CW. Le décodeur cherche la tonalité (200 à 1200 Hz), mesure l'enveloppe, apprend la vitesse sur les premiers éléments (5 à 60 mots par minute) et rejoue la dernière seconde quand il trouve un signal pour ne pas perdre le début. Un panneau de **réglages** s'affiche **sous le texte** (appliqués tout de suite, enregistrés, exportés avec les réglages) : tonalité automatique ou manuelle (200 à 1200 Hz) ; filtre adapté à la vitesse (inspiré de MRP40) ou largeur fixe (30 à 400 Hz) ; **AFC** (suivi de dérive) ; **AGC** lent, moyen ou rapide (évanouissements) ; vitesse automatique ou manuelle (5 à 60 mots/min) ; seuil de détection (30 à 80 %) ; squelch signal/bruit (×3 à ×30) ; seuil de fin de lettre (1,5 à 4 points) et de fin de mot (4 à 9 points) ; « Valeurs par défaut ». Le moteur de MRP40 lui-même est fermé et commercial : il n'est pas repris, seuls ses principes le sont.

**RTTY** : mode USB ou LSB (au moins 500 Hz de bande), sur un signal RTTY (14.080 à 14.099 MHz…). Le décodeur cherche la paire de tonalités et essaie en parallèle plusieurs débits et les deux polarités ; il affiche celui dont les trames sont valides (alphabet Baudot lettres/chiffres). Panneau de **réglages** sous le texte : **vitesse** (automatique, 45,45, 50, 56,88, 75 ou 100 bauds) ; **décalage** (automatique, 85, 170, 200, 425, 450 ou 850 Hz) ; **polarité** (automatique, normale = mark sur la tonalité basse, inversée) ; fréquence de la tonalité basse automatique ou manuelle (500 à 2900 Hz) ; AFC ; « une espace ramène en lettres » (UOS) ; squelch ; « Valeurs par défaut ».

**WSPR** (1.11) : mode USB, sur une fréquence WSPR (14.0956, 7.0386, 10.1387 MHz… : fréquence de la porteuse + 1500 Hz). Tranches de 2 minutes alignées sur l'heure UTC (l'heure du téléphone doit être exacte) ; les résultats arrivent à la fin de chaque tranche : heure UTC, SNR, DT, fréquence audio, indicatif, locator, puissance. Seuls les messages de type 1 sont décodés (pas les préfixes ni les indicatifs hachés). Tous les signaux entendus sont cherchés, y compris plusieurs à quelques hertz les uns des autres (correction 1.11 : deux signaux proches d'un plus fort étaient écartés) ; la limite est le niveau : environ −28 dB dans 2500 Hz, et la qualité du son du WebSDR (CAG, compression) peut en faire perdre. **JT9** (sous-mode A, 1.11) : mode USB, sur 14.078, 7.078, 3.578 MHz… ; tranches d'une minute ; messages standard (CQ, indicatif, locator, report, RRR, 73) ; pas de texte libre vérifié, pas de sous-modes B à H ni de JT65. Les deux décodeurs ont été essayés sur des signaux synthétiques (WSPR jusqu'à environ −28 dB, JT9 jusqu'à environ −24 dB dans 2500 Hz, 6 signaux simultanés, aucun faux décodage sur du bruit) et sur des enregistrements réels de WSJT-X, aussi sur le téléphone (7 messages chacun) ; pas encore sur un vrai signal reçu par le WebSDR.

**Fenêtre du décodeur** : la zone de texte reçu est encadrée et occupe toute la place libre ; les réglages (CW, RTTY, PSK31, SSTV) se placent dessous avec la hauteur de leur contenu (ascenseur seulement s'ils dépassent la moitié de l'écran).
**PSK31 / PSK63** (1.10) : mode USB, sur un signal PSK31 (14.070, 7.035, 3.580 MHz…). Le décodeur cherche tout seul le signal le plus fort entre 300 et 2900 Hz (spectre toutes les 0,5 s), s'accroche, suit la dérive (AFC), retrouve le rythme des symboles, démodule en différentiel et décode le Varicode ; le texte s'affiche au fil de l'eau, aussi sur l'écran principal. Panneau de réglages sous le texte : fréquence automatique ou manuelle (300 à 2900 Hz), vitesse PSK31 (31,25 bauds) ou PSK63 (62,5 bauds), AFC, squelch (cohérence de phase, 60 à 98 %). Une porteuse qui n'est pas du PSK (CW, RTTY…) est écartée au bout de 6 s et ignorée 90 s. QPSK31 et la correction d'erreurs ne sont pas pris en charge. Essayé sur signaux synthétiques (SNR de 5 dB dans 2,4 kHz, décalage de 9 Hz) et sur le téléphone avec un fichier son injecté ; pas encore sur un vrai signal.

**SSTV** (1.10) : mode USB (au moins 2,4 kHz de bande), sur une fréquence SSTV (14.230, 7.033, 3.730 MHz…). Le **mode est reconnu tout seul** par son code VIS : Robot 36 et 72, Martin M1 et M2, Scottie S1, S2 et DX, PD50, PD90, PD120, PD160, PD180, PD240, PD290, Wraase SC2-180 et, depuis la 1.11, Martin M3 et M4, Scottie S3 et S4, Wraase SC2-120, Pasokon P3, P5 et P7, Robot 24, 12 et 8 en noir et blanc (26 modes). L'image se construit ligne par ligne dans la fenêtre du décodeur ; l'impulsion de synchro de chaque ligne est retrouvée (correction de la dérive d'horloge et du décalage d'accord). **Incrustation** : en bas de l'écran principal, à la place du texte FT8, l'image en petit format (au plus 42 % de la largeur et de la hauteur de la zone WebSDR), un appui ouvre la fenêtre ; la case de la fenêtre la masque. **Enregistrement automatique** à la fin de chaque image (case « Enregistrer automatiquement les images », cochée par défaut) en PNG dans **Images › PhoneSDRLink** (Android 10 et plus, visible dans la galerie, sans autorisation ; Android 8 et 9 : dossier de l'application) ; une image interrompue d'au moins 16 lignes est enregistrée avec `_partiel` dans le nom. Le bouton **« Ouvrir le dossier des images enregistrées »** ouvre le dossier dans le gestionnaire de fichiers, ou la galerie à défaut. Essayé sur images synthétiques (les 15 modes, bruit, erreur d'horloge de 0,05 %, décalage d'accord de 60 Hz) et sur le téléphone avec un fichier son injecté ; pas encore sur un vrai signal. **Réglages SSTV** (1.11) : une seule ligne avec deux menus déroulants de 1 à 10. **Sensibilité** (5 par défaut) : plus le chiffre est haut, plus le décodeur accepte les signaux faibles (code de début, synchros, lignes), au risque de quelques fausses détections. **Perte data** (4 par défaut) : temps pendant lequel le décodeur continue une image quand le signal disparaît (3, 5, 8, 12, 18, 25, 35, 50, 75, 120 s pour 1 à 10) ; si le signal revient dans ce temps, l'image reprend à la bonne ligne (les lignes perdues restent grises), sinon l'image est enregistrée telle quelle et le décodeur se remet à l'écoute et retrouve le mode tout seul par les impulsions de synchro (même mode : reprise à la bonne ligne ; autre mode : nouvelle image). Le bouton Info de la fenêtre l'explique. En essai sur signaux synthétiques à 6 dB de rapport signal/bruit : la sensibilité 1 échoue, 5 et plus décodent la plupart des modes ; aucune fausse détection sur 600 s de bruit à aucun niveau. **Image prise en cours de route** (1.11) : quand le début (code VIS) a été manqué, le décodeur cherche les impulsions de synchro à 1200 Hz ; cinq impulsions au rythme exact d'un des 15 modes (et de la bonne durée) donnent le mode et la réception commence à cette ligne : la première ligne reçue devient le haut de l'image (le haut réel manque). Essayé sur les 15 modes et sur du bruit seul (aucun départ en 5 minutes). **Nouvelle image pendant une image** (1.11) : le code VIS est cherché en permanence, même pendant la réception d'une image ; si une autre image commence, la précédente est abandonnée (enregistrée « _partiel » si elle a au moins 16 lignes) et la nouvelle est décodée. Quand le signal disparaît (plus de synchro pendant 10 lignes ou 8 s), le décodeur revient à l'écoute tout seul. **Modes ajoutés en 1.11** (11 de plus, 26 au total) : Martin M3 et M4, Scottie S3 et S4, Wraase SC2-120, Pasokon P3, P5 et P7, Robot 24, 12 et 8 en noir et blanc (les modes à moitié de lignes, M3, M4, S3, S4, Robot 12 et 8, sont affichés avec des lignes doublées). Leurs durées viennent des tableaux de slowrx et de libsstvenc ; ils sont vérifiés seulement par le banc d'essai (le générateur de test suit la même description), pas sur un vrai signal ; les codes VIS de Scottie S3 et S4 (52 et 48) ne sont pas confirmés par une source. **Pas pris en charge** : Robot 24 en couleur (durées non confirmées), AVT 90 et la famille AVT (pas de description complète trouvée : elle n'a pas d'impulsion de synchro à chaque ligne), YoniQ (mode propriétaire de MMSSTV-YONIQ, sans spécification publique), FAX480 et les modes MMSSTV étendus (MP, MR, ML). Scottie DX est pris en charge depuis la 1.10.
**FreeDV RADE V1** : mode USB, sur un signal RADE (14.236 MHz…). La réception classique du WebSDR **continue tant qu'aucune trame RADE n'est décodée** ; dès que de la parole est produite, le son du WebSDR est coupé et la parole FreeDV est jouée ; 1,5 s sans parole, retour à la réception classique. Il demande un téléphone **64 bits**. Il occupe environ **un tiers d'un cœur** du processeur tant qu'il tourne (calcul 3 fois plus rapide que le temps réel sur un OnePlus). La coche **FreeDV auto** (SET, juste sous le bouton Décodeur ; décochée par défaut) le lance **en permanence** pendant l'écoute classique, et dès le démarrage de l'application : on écoute le trafic normal et, si l'on tombe sur du FreeDV, il se décode tout seul. Il est **suspendu pendant qu'un autre décodeur est actif** et relancé quand celui-ci s'arrête (bouton Arrêter) ; en mode auto le bouton SET ouvre toujours les réglages.

**Fichiers et mémoire** : aucun fichier n'est écrit (tout est en mémoire), sauf les images SSTV si l'enregistrement automatique est coché (Images › PhoneSDRLink). Les fichiers temporaires (mise à jour téléchargée, copies de réglages, cache de la page) sont supprimés au démarrage et à la fermeture de l'application.

**Limites** : FT2 n'est pas pris en charge (deux versions incompatibles entre elles, sans spécification publiée, code sous licence GPL). CW et RTTY ont été validés sur des signaux synthétiques et à l'écran ; en RTTY, le début d'un message peut sortir en désordre si le décodeur prend la trame en route (motif RYRY). FreeDV RADE V1 a été validé sur un enregistrement hors antenne (114 s synchronisées sur 120 en 1.9 ; 314 s sur 327 en 1.11 avec les sources de FreeDV 2.4.1) et pour la bascule du son, pas encore sur un signal en direct ; la V2 n'a été essayée qu'en bouclage dans le téléphone. L'APK pèse environ 17,2 Mo en 1.11 (9,7 Mo en 1.9 et 1.10), presque tout en poids de réseaux de neurones pour FreeDV. Composants de tiers : ft8_lib (MIT), radae_nopy et rade_c (BSD), Opus (BSD), voir THIRD-PARTY-NOTICES.md.
## Reprendre ses réglages de SDRLink (PC) dans PhoneSDRLink

Les réglages de SDRLink pour PC s'importent dans PhoneSDRLink (même format de fichier `settings.ini`) : favoris WebSDR et listes de favoris, mémoires de fréquences, profils de scan, zones non scannées, langue, mode sombre, nom donné aux WebSDR.

1. Dans **SDRLink sur PC** : exporter tous les réglages vers un fichier `.ini` (le fichier de travail est aussi `%APPDATA%\SDRLink\settings.ini`).
2. Copier ce fichier sur le téléphone (câble USB, Drive, e-mail… ; par exemple dans « Téléchargements »).
3. Dans **PhoneSDRLink** : **SET › Importer des réglages…**, choisir le fichier (dans le sélecteur de fichiers : menu en haut à gauche › Télécharger).
4. Cocher ce qu'il faut importer :
   * **Configuration** (affichage, langue, nom…) ;
   * **WebSDR** (favoris et listes de favoris, avec leurs noms) ;
   * **Mémoires de fréquences** ;
   * **Scan** (réglage, zones non scannées, profils de scan nommés).
5. Choisir : **garder les éléments déjà dans l'application et ajouter ceux du fichier** (sans doublons : même adresse dans la même liste, même nom de profil) ou **les supprimer et les remplacer** par ceux du fichier.

Les catégories absentes du fichier sont grisées. Dans l'autre sens, **SET › Exporter tous les réglages…** crée un fichier `PhoneSDRLink-settings.ini` qui sert de sauvegarde (à réimporter dans PhoneSDRLink après une réinstallation ou sur un autre téléphone). Essayé avec un vrai fichier de SDRLink pour PC : 166 favoris, 5 listes, 3 mémoires et 2 profils de scan repris correctement.
## Installer sur un smartphone Android

Android 8 ou plus. L'application n'est pas dans le Play Store : on installe le fichier APK à la main.

1. Sur le téléphone, ouvrir la [dernière version](https://github.com/F5pbgLudovic/PhoneSDRLink/releases/latest) et télécharger `PhoneSDRLink-x.y.apk` (ou le télécharger sur PC et le copier sur le téléphone).
2. Ouvrir le fichier (notification de téléchargement, ou application Fichiers › Téléchargements).
3. Android demande l'autorisation d'installer des applications « de sources inconnues » pour l'application qui a ouvert le fichier (Chrome, Fichiers…) : **Paramètres › Autoriser depuis cette source**, puis revenir et **Installer**.
4. Ouvrir **PhoneSDRLink**. Au premier lancement, la recherche des WebSDR se lance toute seule : cocher ceux qu'on veut garder et « Ajouter les cochés aux favoris ».

Pour mettre à jour : installer le nouvel APK par-dessus (même signature, les réglages sont conservés), ou SET › « Vérifier les mises à jour ».

### Si un antivirus ou Play Protect proteste

Un APK qui ne vient pas du Play Store, signé par un auteur inconnu, est souvent signalé « suspect » par les antivirus (c'est une détection prudente fondée sur la rareté du fichier, pas sur un défaut trouvé). PhoneSDRLink ne demande que l'accès à Internet, au réseau et aux réglages audio ; il n'accède ni aux contacts, ni aux SMS, ni à la localisation, ni au micro. Ses sources sont toutes publiques dans ce dépôt.

* **Google Play Protect** (« Application non reconnue » / « Bloquer ») : toucher **Plus de détails** puis **Installer quand même**. Si le message ne propose que « OK », ouvrir le Play Store › profil › **Play Protect** › roue dentée › désactiver temporairement « Analyser les applis avec Play Protect », installer, puis le réactiver.
* **AVG, Avast, Norton, Kaspersky, etc.** (« Application suspecte trouvée ») : choisir **Annuler** / **Ignorer** (surtout pas « Désinstaller »), puis dans l'antivirus **ajouter PhoneSDRLink aux exceptions** (AVG : Menu › Paramètres › Exceptions › Ajouter une application ; l'intitulé varie selon la marque). L'alerte peut revenir après chaque mise à jour.
* **Vérifier le fichier** (facultatif) : l'empreinte SHA-256 de chaque version est indiquée dans les notes de la release ; on peut la comparer à celle du fichier téléchargé (sous Windows : `Get-FileHash fichier.apk`).
* **Compiler soi-même** : les sources sont ici ; voir « Compiler » plus bas.
* Si l'installation échoue en disant que l'application est déjà installée avec une autre signature (APK compilé par quelqu'un d'autre), désinstaller d'abord l'ancienne version.

## Compiler / Build

`tools\install-toolchain.ps1` (une fois : JDK 17 + Gradle + SDK Android portables dans `toolchain\`, accepte les licences du SDK Android), puis `.\build.ps1` → `dist\PhoneSDRLink-<version>.apk`. L'installateur ajoute aussi le **NDK 26.1.10909125** et **CMake 3.22.1** : le code natif des décodeurs (`app/src/main/cpp` : ft8_lib, radae_nopy, Opus, enveloppes `sdrdec_*.c`) est compilé par Gradle pour arm64-v8a (FT8, FT4 et FreeDV RADE) et armeabi-v7a (FT8 et FT4 seulement). La clé de signature `phonesdrlink.jks` n'est pas publiée : sans elle l'APK est compilé non signé (à signer avec sa propre clé pour l'installer).

Outils de mise au point (adb) : `adb shell am start -n fr.f5pbg.phonesdrlink/.MainActivity --es url <adresse>` ouvre un WebSDR ; `--ez dump true` copie les réglages dans `Android/data/fr.f5pbg.phonesdrlink/files/` ; `--es js "<code>"` évalue du JavaScript dans la page (résultat dans `logcat -s PSDR`).

Bibliothèques embarquées : [lamejs](https://github.com/zhuker/lamejs) (encodeur MP3, LGPL-3.0) ; décodeurs : [ft8_lib](https://github.com/kgoba/ft8_lib) (MIT), [radae_nopy](https://github.com/drowe67/radae_nopy) (BSD) et [Opus](https://github.com/xiph/opus) (BSD), voir `THIRD-PARTY-NOTICES.md`.
